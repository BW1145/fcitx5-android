# 1.3.2 维护与性能

基线：`personal-ice@5fd75bb`。沿用完整与轻量共用源码、包名、签名及现有用户数据格式。

## 工作与验证

1. 候选偏好共享缓存：稳定输入不重复读取、解析规则；修改、恢复、导入后生效，点击、空格及数字选词保持一致。
2. AI 会话后台读写：按 ID 加载正文，摘要缓存与每批 20 条历史，保留全文搜索、双草稿、隐私临时对话及取消/删除语义。
3. 共用编辑会话：独立编辑器与输入路由，搜索和 AI 各自管理内容。
4. 上游补丁：按组件集中定义，共用应用入口，保持固定版本与校验；生成源码可重复准备。
5. 回归与材料：按行为拆分长测试，归档一次性发布流程及概念稿，保留有效检查。

## 验收

- 固定空数据与 5,000 条候选偏好、500 份各含 20 条消息的会话，对比耗时及内存；计时作为比较，确定性检查作为 CI 条件。
- 验证旧 JSON/TSV/ZIP、学习快照恢复与合并、导出前待保存草稿，以及 full → lite → full 覆盖。
- 沿用原有中文/日语、联想与模型、宏、剪贴板、主题及 Android 兼容检查。
- 本地检查完成后统一推送用户 fork，确认构建启动后交付。

## 进展

- 已完成候选共享缓存、词库修改及快照恢复后的主动刷新、AI 后台存储与分批历史、共用编辑会话、补丁集中及历史材料归档。
- 本地 17 项检查通过，安卓回归源码编译通过；新增 AI 编辑器关闭与迟到输入隔离、当前候选规则即时更新的实际触屏用例。
- 候选前端通过 Android 目标编译检查。新的 CMake 接口已生成并编译 Rime、Anthy 的全部插件源码，产出两份静态检查库；固定依赖变换与原实现逐文件一致。
- 500 份各含 20 条消息的本地 JVM 对照：整库读取中位约 84 毫秒，按 ID 打开约 0.6 毫秒，首批 20 条摘要约 0.2 毫秒。首次建立索引约 0.5 秒，在后台运行。堆内存采样及 p95 随构建报告保留；这些数据用于存储路径比较。
- 覆盖升级使用已通过所有检查的 `1.3.1@5fd75bb` APK，在旧程序上建立 AI、常用内容、宏、剪贴板、学习词条和快照，再安装新版检查内容和文件哈希，并继续 full → lite → full。
- 旧 APK 固定为用户 fork 的 `custom-1.3.1` 发布中的 `upgrade-fixture-1.3.1-x86_64.zip` 测试附件，工作流校验 SHA256，后续构建沿用这一基线。
- 搜索词重复通知复用当前结果；相同结果保留原视图，后台刷新期间可点击当前可见条目，关闭面板后结果动作失效。回归测试覆盖输入组合变化与点击交错。
- 拆分后的模型、联想测试先等待 Rime 词库就绪；AI 面板测试在正文提交完成后重新打开工具栏，继续验证待处理按键隔离。

## 重点验收对应

| 要求 | 检查 |
| --- | --- |
| 修改词条、恢复备份后候选立即更新 | 当前拼音保留，规则修改无需再按键即可隐藏或恢复候选；原生快照恢复/合并后重新输入立即使用对应偏好。 |
| AI 回复、草稿、删除互不覆盖 | 草稿更新保留已完成回复；删除后迟到回复和草稿不复活记录；导入后先前请求和草稿失效。 |
| AI、搜索输入保持隔离 | 两个实际触屏用例覆盖输入、候选或宏，以及关闭时原生队列仍有待处理按键的情况。 |
| 覆盖安装、导入备份数据可用 | 旧版覆盖升级和完整/轻量切换；导出前等待草稿保存，原有 JSON/ZIP 读取与导入后缓存刷新。 |
